3. Theme-by-theme detail 

Theme A: Project Copley, an open knowledge layer for agents 

A1. "Retrieval got solved. Trust didn't." (teaser, early-to-mid August) 

Work IQ made Copilot context-aware by default across Microsoft 365. It also exposed the harder problem: an agent can retrieve a number, policy or process "with no idea whether it's current, correct, or safe to act on." 

Proposal: an automated, validatable schema that extends Work IQ into a consistent knowledge framework for cross-platform agents and Microsoft systems. "Not another ontology, and not a rip-and-replace." 

It draws on Google's Open Knowledge Format (OKF), MCP, Agent Skills and semantic-web provenance patterns, in one Git-native format. 

Three layers, one source of truth: pointers to raw source documents (no copies, no drift), curated knowledge with real owners and workflows, and a schema that keeps both honest. 

Content still lives in SharePoint, "the knowledge layer for business AI." 

Call to action: comment to join a small working discussion. "More soon, including a name I'm oddly proud of." 

1,572 impressions, 17 reactions, 17 comments. 

A2. Project Copley announcement (mid-August, posted to the feed and to the Information & Knowledge Management Executive Network group) 

Introduced Project Copley by name: "an open, early-stage effort to build a governed knowledge layer that extends Work IQ and works for cross-platform agents too." 

Builds on Open Knowledge Format, JSON Schema and SHACL, MCP and Agent Skills, with open governance patterns borrowed from OCP. "No new ontology, no platform." 

"Nothing about Copley is settled, and that's the point." 

First community call: Thursday, August 20, 8:00 AM PT, 45 minutes. Brief framing, then open discussion on whether the profile is warranted, where it breaks outside Microsoft estates, and what people have already built. 

"Everyone's welcome, especially if you think we've got it wrong." 

Group version: positioned Copley against Google OKF. Work IQ handles contextual retrieval but "can be a black box." Goal: a visible knowledge layer that all AI can use, "not just Copilot." Mentions an Easter egg in the blog post about Chris's KM history before Project Cortex and Viva Topics. 

Feed: 733 impressions, 10 reactions, 5 reposts. Group: 72 impressions. 

Newsletter hook: August set the thesis and held the first call. If September content includes Copley follow-up, frame it as "what the community told us." 

Theme B: SharePoint as the AI publishing layer 

B1. Roadmap ID 569208: HTML pages in SharePoint (late August; top professional post) 

Create HTML with Copilot in SharePoint, or upload your own. In the pages library, SharePoint renders it as a page that you can keep editing and share like any other page. It sits alongside ASPX pages: "additive, not a replacement." 

Status: in development, rollout starts October 2026, worldwide, GA and Targeted Release. 

Bigger point: Synozur already uses a custom SKILL file (Markdown that tells Copilot how to pull, structure and style data) to produce a live HTML dashboard on demand. "The skill is the template and the HTML is the result." 

The missing piece was the "last mile," meaning somewhere native to put the dashboard. With 569208, the skill generates HTML, the HTML lands in the pages library, and it renders as a real SharePoint page under existing governance and permissions. "No new platform. No shadow site. No 'where does this live?' meeting." 

Pointer to the open Copilot skill repo: aka.synozur.com/md-skills 

Closing line: "If you've been treating custom skills as a text-generation trick, this is the moment to reconsider. They're a publishing pipeline now." 

4,749 impressions, 70 reactions, 5 comments, 7 reposts. 

B2. Synozur Alliance summer SharePoint recap (company post with Chris's comment) 

Five changes since June: 

Lists became live apps: Copilot in SharePoint builds an interactive dashboard that stays connected to the list. 

Personal skills save as Markdown in OneDrive and work across every site. Enterprise store plugins land there too. 

The button web part can launch a custom Copilot prompt or a Power Automate flow, which puts the prompt "where the work already is." 

Describe-it workflows: Copilot assembles the trigger, conditions and actions from plain language. 

Restricted SharePoint Search is retiring (no new enablement after July 31). Restricted Content Discovery and Restricted Access Control take over.

Theme C: Copilot's front door and data protection 

C1. The redesigned Copilot app (before August 18) 

Microsoft is consolidating personal, work and school access into one Copilot app. On the consumer side, Podcasts, Mico, Copilot Labs, Group Chat and Deep Research retire from the consumer app starting August 18. Deep Research continues as Researcher for Microsoft 365 Premium. 

For tenants, little changes: a new icon, work and personal accounts stay separate, and all security, compliance and admin controls still apply. "This is not a governance event." 

Field insight: clients say M365 Copilot "doesn't really work," and it turns out they have been using the free Copilot in Edge, with no tenant grounding. "That's not an edge case. (No pun intended.)" 

"The hardest adoption problem I see isn't 'Copilot can't do this.' It's 'the user never actually met Copilot.'" 

Advice for IT: put August 18 on the calendar, tell users the icon is changing, and move on. For skeptics: "check which Copilot you were using first." 

1,763 impressions, 12 reactions, 4 comments. 

C2. Microsoft increases the scale of Copilot data protection (after August 27) 

"Copilot readiness is still a data-governance problem before it is a prompting problem." 

Microsoft's August 27 security update: Purview auto-labeling now processes up to 500,000 SharePoint and OneDrive files per day, up from 100,000. 

Entra Tenant Governance adds centralized policies, delegated cross-tenant administration, configuration-drift monitoring and visibility into shadow tenants. 

New Secure Now guidance in Security Exposure Management covers limiting agent-initiated actions, hardening attack surfaces and constraining identities and permissions. 

Caveat: the 5x increase "doesn't replace classification design, ROT remediation, DLP testing, or Entra privilege review." 

Newsletter hook: This leads directly into September's Purview network-layer DLP and Claude Enterprise coverage. Governance can run as one thread across both months. 

Theme D: Knowledge management, the human side 

D1. "Knowstalgia: The Heart of Knowledge Management in the AI Era" (blog post, synozur.com) 

Builds on a paper by Katrina (Kate) Pugh, Ph.D., Jonathan Ralton, Marc Solomon, Andrew Trickett and Eve Porter-Zuckerman: "Knowledge Managers Bring Collectivity, Nostalgia, and Selectivity to the AI Ecosystem." 

They recast nostalgia as careful curation of exemplars, which teaches AI what good looks like. Chris coined "knowstalgia." 

Proposal: "don't strip out the emotion." People remember stories, pride and hard-won lessons more than policy documents. As AI becomes coach, companion and confidant, the systems worth building carry "both head and heart." 

P.S.: Kate and Chris started discussing this in February 2025, and he acknowledged "the irony of taking a year and a half to finalize a post about the time dimension of knowledge retrieval."

S1. Copilot in SharePoint GA and a one-skill list dashboard (late September) 

Copilot in SharePoint starts rolling out to general availability on September 30. "The first thing I'd build with it is a live dashboard from a SharePoint list." 

What GA includes: everyday work (asking questions; building pages, lists and libraries; creating HTML and Office files; Autofill metadata) comes with the Microsoft 365 Copilot license. 

Bigger jobs (large content sets, whole sites, scheduled AI automations, real-time Autofill) are billed as "advanced work" using Copilot Credits through an admin-center spending policy. 

Skills are Markdown files stored per site in the Agent Assets library. The preview's PowerShell opt-in cmdlets are going away; existing settings stay until November 1. 

How-to: get the sharepoint-list-dashboard skill from Synozur's public repo, upload SKILL.md to Agent Assets > Skills > sharepoint-list-dashboard, then ask Copilot in SharePoint for an executive dashboard. The result is one HTML file in SharePoint that refreshes from the list. For Excel data, use excel-to-html-dashboard from the same repo. 

Enterprise read: no tenant-wide switch for skills. Anyone with Edit can create one; anyone with View can run one. Skills can't reach outside systems or run custom code, and stay within the user's permissions. "The bigger risk is a weak skill spreading across a site." 

Advice: break permission inheritance on Agent Assets where needed, govern SKILL.md files with sensitivity labels, retention and auditing, and set the Copilot Credits spending policy before users discover advanced features. 

Links: Synozur skills repo (Apache 2.0), PnP community skills, Microsoft Learn. 

S2. Copilot rebuilt around Home, Code and Autopilot (September) 

"Microsoft just rebuilt Copilot around three tabs and quietly changed how you'll pay for it." 

Home merges Chat and Cowork, with Word, Excel and PowerPoint running inside Copilot as real editable files. Code lets non-developers describe an app, dashboard or automation; same technology as GitHub Copilot, sandboxed and tenant-hosted. Autopilot (formerly "Scout") is a persistent agent working in Teams and Outlook; private preview at the end of September. 

Copilot Managed Runtime enters public preview, with new FinOps for AI controls. 

Pricing splits: fixed-cost licensing for everyday AI, usage-based billing for Cowork, Code, Autopilot and frontier models. 

Enterprise read: "The pricing split is the real news." Citing CNBC projections of 50 million+ commercial seats with a Copilot license, Microsoft is moving the expensive parts to consumption. "If your 2027 budget assumes $30 per seat and stops there, rebuild the model now." 

Open questions for leaders: who approves Autopilot agents acting in Outlook for a user, and whether Code apps built by finance analysts fall inside the Purview and DLP boundary. "Ask that before the Frontier rollout reaches your tenant, not after."

S4. Classic SharePoint gets an end date; Flexible Sections get releases (September) 

Chris was in the room in San Francisco on May 4, 2016, when Microsoft announced the future of SharePoint (modern pages, libraries, canvas). "Last week, Adam Harmetz and team set the clock on the old one." 

March 1, 2027: no new classic publishing sites (AllowClassicPublishingSiteCreation locks to False). 

October 1, 2028: classic user-created pages go read-only in every tenant: wiki, web part, blog, publishing and custom ASPX pages. DenyAddAndCustomizePages locks to True. Nothing is deleted. 

The same week, Flexible Sections added column layout guides, a persistent gridlines toggle, and conversion from standard sections without losing layout. "One side gets a date, the other gets releases." 

Advice: "start with discovery, not migration." Purview Audit now logs ClassicPageCreated, ClassicPageEdited and ClassicPageViewed; run the Microsoft 365 Assessment Tool. "The rest will find the 2014 intranet home page that finance quietly runs on. Better to find it now than in 2028." 

1,773 impressions, 31 reactions, 5 comments, 1 repost. 

S5. GPT-6 Astra: real computer use, unconvincing AGI claim (late September or early October) 

On OSWorld 2.0, Astra scored 72.6% at about 40 minutes per task, versus 65.7% at 75 minutes for GPT-5.6 Sol. Demos: a Form 1040, a circuit board layout, Power BI, and frontend QA. 

Optimistic take: most enterprise work happens in vendor portals nobody will write a connector for. "If computer use survives those sites, a large share of integration backlog goes away." 

After the Hugging Face incident, OpenAI built a scope eval; Astra scored 0% (out-of-scope) where Sol hit 48% without safeguards. But staying in scope and clearing a bot check are different problems, and nothing says whether Astra may solve a reCAPTCHA. "That's a design constraint, not a detail." 

On AGI: Greg Brockman says we're there, but GDPval, OpenAI's own benchmark for economically valuable work, wasn't in the launch materials. 

Source: BlueTrail Intelligence Report. 620 impressions.

5. Synozur blog posts and Polaris episodes (August–September 2026) 

From synozur.com/insights. Where a blog post and a LinkedIn post cover the same topic, the final analysis should merge them. 

Blog posts 

BP1. "Knowstalgia: The Heart of Knowledge Management in the AI Era" (August 5) 

Long-form version of LinkedIn item D1. Pugh et al. use "nostalgia" to mean curating historical exemplars that teach AI what good looks like. Chris pivots to the emotional side of memory: stories and feelings make knowledge stick and improve recall, engagement and culture. 

Draws on his records management experience at Microsoft and AIIM: older information often still has real value ("oldies but goodies"). 

Summarizes the paper's three behaviors: Collectivity (humans checking and refining AI suggestions), Nostalgia (training on curated past examples) and Selectivity (being precise about what data goes into AI). 

URL: https://www.synozur.com/insights/knowstalgia-the-heart-of-knowledge-management-in-the-ai-era 

BP2. "Retrieval Got Solved. Trust Didn't." (August 10, the Project Copley launch post) 

Long-form version of LinkedIn items A1 and A2. Work IQ solved retrieval, but "finding isn't trusting." This is a knowledge problem, not a retrieval problem, and the answer has to be written down somewhere the retriever can read it. 

Google's Open Knowledge Format (OKF) is the first serious attempt to formalize the pattern: portable markdown bundles, one concept per file, with YAML frontmatter and trust fields (sources, verification, staleness, lifecycle). Its best design choice is that it is "a format, not a platform." No equivalent existed for Microsoft 365. 

Work IQ brokers retrieval across the tenant's graph of people, work, content and skills, and Chris says Microsoft 365 customers should use it. What no retrieval layer does on its own is explain why an answer should be trusted, whether it is current, how a number was computed and approved, or what an agent may remember and act on. 

Copley is a draft spec and a public repo: a schema that validates in CI, pointers to real sources, curated knowledge with named owners, and agents and workflows that keep it current. It extends Work IQ and works for non-Microsoft agents. 

URL: https://www.synozur.com/insights/retrieval-got-solved-trust-didnt-meet-copley 

Community call event page (August 20, Teams webinar): https://www.synozur.com/events/project-copley-building-an-open-knowledge-layer-for-work-iq-and-cross-platform-a 

BP3. "AI-first operating model: the difference between AI activity and AI ROI" (August 5) 

Many AI initiatives stall because organizations focus on the technology rather than the operating model needed for measurable outcomes. 

An AI-first approach ties governance, ownership, decision-making, adoption and accountability to clear P&L impact. The path is not more pilots. It runs from AI-ready to AI-enabled to AI-first, measured by revenue, productivity, speed and business results.
