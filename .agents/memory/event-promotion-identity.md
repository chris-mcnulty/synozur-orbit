---
name: Event promotion identity
description: Shared Visual Assets ownership, webinar branding, and main-event-only promotion requirements.
---

Webinars are valid events with no session records and no separate event logo. Company branding is sufficient; do not require fictitious sessions or an event-specific mark to enable promotion.

**Why:** Users reuse their own webinar visuals and need additional branded-text choices alongside—not instead of—their originals. An image pool supplies visual variety, not an implicit request for more social posts.

**How to apply:** Treat main-event registration promotion as a first-class workflow. Keep original images independent, create separate overlay variants, and determine sessionless drop volume from promotion dates/cadence rather than pool size. Preserve the distinct existing multi-session conference workflow.

Event graphics and background photos belong in Orbit's existing Visual Assets library. Events select shared assets and retain event-specific roles/render recipes; they must not maintain a disconnected reusable-image library.

Event assets must have a persisted `Event` topic tag, not only an association badge. Existing Visual Assets must be selectable as event originals as well as compositor templates, without requiring another upload.

**Why:** The user explicitly rejected a separate event-image library and approved connecting existing images to Visual Assets while preserving files and post references.

**How to apply:** Register uploads and render outputs as shared assets, retain event/post identities and historical URLs, and support selecting existing library originals. Removing an image from an event pool must not archive the reusable asset for unrelated uses.

Anchor promotion must not silently degrade to text-only posts. Auto-render for an event with no anchor pool should provision branded composites; failed or missing anchor images must block replacement of the existing batch.

**Why:** Events with session graphics but no manually configured anchor pool produced approved anchor posts without images. The user identified this as a broken batch requiring cancellation and regeneration, not an acceptable fallback.

**How to apply:** Apply image readiness to anchors and sessions alike, reuse existing pool choices, and keep regenerated posts in draft until reviewed. A batch reset must preserve published history and avoid mutating sends already claimed by a worker.
